WhisPaste is a voice-input utility: press a global hotkey, speak, and the
transcribed text is inserted at the current cursor position in whatever app
is focused (Mail, Notes, a browser, an IDE, etc.). All speech-to-text
processing runs on-device by default (Whisper/Parakeet); cloud providers are
opt-in and never touch our servers.

TEXT INSERTION AND THE ACCESSIBILITY PERMISSION
To insert text at the cursor, WhisPaste posts synthetic keyboard events via
the PostEvent API (CGEvent/CGEventKeyboardSetUnicodeString), gated by
macOS's PostEvent TCC permission (surfaced to the user as "Accessibility").
This is the same system-level channel other App Store voice-input and
automation utilities use for the same purpose. WhisPaste does not use the
Accessibility (AXUIElement) API to read or observe other apps — it only
posts the keystrokes for the text it just transcribed, and never reads,
records, or transmits what is on screen or in other apps.

Granting this permission is optional: without it, WhisPaste falls back to
copying the transcribed text to the clipboard for a manual Cmd+V paste.
Permission can be granted, denied, or revoked any time in System Settings >
Privacy & Security > Accessibility; the app explains this trade-off in its
own onboarding before ever prompting for it.

HOW TO TEST
1. Launch WhisPaste, complete onboarding (grants Microphone; Accessibility
   is optional and can be skipped).
2. Open any text field (TextEdit, Notes, a browser address bar).
3. Press the configured hotkey, speak a short sentence, release/press again
   per the chosen push-to-talk or toggle mode.
4. Transcribed text appears at the cursor within seconds. Without
   Accessibility granted, it's placed on the clipboard instead.

No account, sign-in, or demo credentials required — works fully offline.

RESUBMISSION NOTE (Aug 2 submission resolved items 5.1.1(iv), 5.6.3, and 5
below; Guideline 2.4.5 was re-flagged Aug 4 and is answered below)

Guideline 5.1.1(iv) — Microphone permission wording
The custom pre-permission screen's button was relabeled from "Grant
Access" to "Continue" (and the equivalent Auto-Paste/Accessibility
pre-permission buttons, not flagged this round but the same pattern, were
relabeled the same way pre-emptively). No pre-permission screen tells the
user how to respond to the native macOS permission dialog itself.

Guideline 2.4.5 — Accessibility permission purpose
The global hotkey does not use Accessibility features: it is registered
via the Carbon Event Manager Hot Key API (RegisterEventHotKey, in the
bundled HotKey.framework), a public API needing no TCC permission. To
verify, turn WhisPaste's Accessibility toggle off in System Settings and
press the hotkey: recording and transcription still work; only the
cursor insertion falls back to a clipboard copy, because that step alone
uses the PostEvent TCC service (CGPreflightPostEventAccess /
CGRequestPostEventAccess). No bundled binary or framework references
AXIsProcessTrusted, AXUIElement*, CGEventTapCreate or a global event
monitor; nm -u confirms this. We also softened the in-app copy to "the
permission macOS calls Accessibility".

Guideline 5.6.3 — Rating request timing
The one-time "thanks for your support" hint shown to Mac App Store users
(with its own "Rate on the Store" / "Star on GitHub" choice, separate from
the general review-prompt flow) no longer fires 2 seconds after onboarding
completes. It now requires at least 12 completed real recordings first —
the same usage bar the general review-prompt flow already used — so it can
no longer appear on first launch or during onboarding.

Guideline 5 — China / OpenAI references
WhisPaste's optional cloud transcription add-on integrates with OpenAI's
API. Rather than attempt to gate that functionality specifically for the
China mainland storefront, we've deselected China mainland from this app's
Availability settings in App Store Connect, so the app (and its OpenAI
references) are not distributed there at all.
