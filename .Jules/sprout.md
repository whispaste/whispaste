## 2026-08-26 - Verify specific widget architecture and required parameters
**Learning:** When updating UI components across different view variants (like `HistoryCardView`, `HistoryCompactView`, `HistoryEntryRow`), each view often has a dedicated sub-widget (e.g. `HistoryEntryCard`, `HistoryCompactRowActions`) that needs the new parameter passed down individually. The exact class names and file scopes might differ from what they seem. Rely on `grep` and `cat` to firmly ground the widget structure in reality before applying patches.
**Action:** Before planning a change across multiple UI components, always run `grep -E "class " <file>` to enumerate all actual classes inside the target file, and read their constructors/build methods directly to map out the exact data-flow path, instead of guessing names and structure.
